# HTML 報告視覺化規格

## 必要結構

將圖表放在排行榜附近，使用單一 HTML 內嵌 `<svg>` 或 `<canvas>` 與原生 JavaScript；不要載入外部套件、CDN、網路字型或外部圖片。所有圖表都要重用與排行榜相同的資料陣列，避免分數漂移。可直接參考並將 `assets/inline_charts.js` 的函式內嵌到報告；發布時仍必須把 JavaScript 寫進單一 HTML，不可以外部 `.js` 檔作執行依賴。

每張圖表至少包含：

- `<figure>` 與一句說明性的 `<figcaption>`。
- `role="img"` 和 `aria-label`，或等效的文字替代描述。
- 顯示單位、分數上限、軸標籤、圖例及資料缺漏規則。
- 圖表下方的 HTML 表格／文字摘要，讓不支援 SVG、Canvas 或色彩辨識的讀者仍能讀取結果。
- 16px 以上的文字；小螢幕使用 responsive 寬度，不以縮小字體塞入圖表。

## 三張固定圖表

### 1. 前十名校正分數長條圖

資料來源為家族多樣化後的前 10 名。Y 軸固定 0–100，長條上標出 `adjusted_score`；標籤過長時使用編號並在圖下提供編號—完整題名對照表。

### 2. 創新性 × 可行性散點圖

X 軸使用創新性分數（0–15）。Y 軸使用可行性輔助指標，必須在 `README.md` 和圖例明確定義（例如學生可操作性、材料取得性與風險的組合），不可把高科技潛力直接當成可行性。每點顯示題目 ID；滑鼠提示不是唯一資訊來源，表格要能查回完整題名、分數與研究家族。

### 3. 風險扣分分布圖

以 `risk_deduction` 顯示每題扣分，或以風險類型堆疊。圖說要清楚寫出「扣分越高代表目前規畫風險越高」，不可用綠色／紅色暗示未經資料支持的品質結論。風險類型為 null 時標示「未分類風險」。

## 篩選與驗證

篩選題目分類、年級、科別、預算或研究週數後，重新繪製三張圖並同步更新題目數。若無符合資料，顯示「沒有符合條件的題目」，不要顯示上一個篩選結果。產出前以瀏覽器或靜態檢查確認：HTML 含三個圖表容器、16px 字級規則、圖表資料筆數與可評估題目數一致，且無 `http://`／`https://` 的外部資源引用。
